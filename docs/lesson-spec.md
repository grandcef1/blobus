# Спецификация урока (движок сервера)

Документ описывает правила, которые исполняет серверный движок урока. Модель ничего из этого не решает:
она получает готовый блок `LESSON_STATE` и следует ему. Код: `server/chat/lessonState.ts` (состояние и
переходы), `server/chat/lessonCatalog.ts` (контент), `server/chat/prompt.ts` (промпт),
`server/routes/chat.ts` (квоты, проверка ответа викторины, запись карточек).

## 1. Состояние урока

`LESSON_STATE` живёт в `lessons.plan` (jsonb, новая миграция не нужна). Значение колонки — документ урока:
`{ plan, state }`, где `plan` — план C-10 (карточка цели, активности, целевые слова), `state` — состояние
движка. Старые строки в плоской форме плана читаются как `state = null`: состояние собирается при первом
ходе, а прогресс не теряется.

Поля `state`:

| Поле                     | Смысл                                                                                                                          |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| `version`                | версия документа состояния (2)                                                                                                 |
| `stage`                  | этап следующего хода: `S0` старт, `S1` крючок, `S2` разминка, `S3` практика, `S4` проверка, `S5` проверочные ответы, `S6` итог |
| `turn_index`             | номер сыгранного хода, с нуля                                                                                                  |
| `turns_left`             | остаток ходов урока (см. pacing)                                                                                               |
| `pacing_mode`            | `NORMAL` / `TIGHT` / `FINAL` / `LAST`                                                                                          |
| `rule`                   | `{ correct_total, correct_streak, mastered, open_error{type,count} }`                                                          |
| `words[5]`               | `{ word, meaning, example, status }`, статус `hidden` / `introduced` / `recognized` / `produced`                               |
| `next_word_due`          | ход, с которого очередное слово обязано быть введено                                                                           |
| `next_activity_type`     | тип активности следующего хода (`choice` / `gap-fill` / `word-order` / `sentence`)                                             |
| `last_activity_types[3]` | три последних типа: ротация и запрет трёх подряд                                                                               |
| `recent_contexts[3]`     | последние ходы `{ text, tokens }`: разные предложения и оценка расхода                                                         |
| `seed`                   | сцена урока из каталога                                                                                                        |
| `twist`                  | твист сцены, появляется после шестого хода                                                                                     |
| `weak_patterns`          | паттерны, помеченные слабыми (см. §6)                                                                                          |
| `checks_done`            | сколько верных проверок пройдено в `S5`                                                                                        |

## 2. Метрики правила

- `rule_correct` — ход без значимой ошибки, без провала викторины и **в другом предложении**
  (сравнение с предыдущей репликой ученика в нормализованном виде).
- `rule_streak` — серия таких ходов подряд; сбрасывается ошибкой.
- `rule_mastered = correct_total >= 4 && correct_streak >= 2` (четыре верных применения, два последних верны).
- `open_error` — открытая ошибка: повторная ошибка того же вида увеличивает `count`, другая ошибка
  сбрасывает счётчик в 1, верный ход закрывает ошибку.
- `words_done` — все пять слов минимум `introduced` и не меньше четырёх — `recognized`; цель урока —
  `produced` у трёх из пяти.

## 3. Этапы и переходы

- `S1 HOOK` (ход 1) → `S2 PRIME` (ходы 2–3) → `S3 PRACTICE`.
- `S3 → S5`, если правило освоено и все слова введены, либо `turns_left <= 1`.
- `S5 → S6` после двух верных проверок (`checks_done >= 2`) или при `turns_left = 0`.
- Любой этап → `S6` при `turns_left = 0`.
- Жёсткий потолок 18 ходов: `turn_index >= 18` → этап `S6` и режим `LAST`.
- Третья повторная ошибка возвращает урок в `S4 CHECK` и помечает паттерн слабым.
- Незавершённый урок продолжается с сохранённого этапа: приветствие повторно не пишется, «первого хода»
  второй раз не бывает.

## 4. Pacing

`A = turns_left`, `R = слов_не_введено + (mastered ? 0 : 2)`.

| Режим    | Условие               | Лимит слов первой части (M1) | Второй части (M2) |
| -------- | --------------------- | ---------------------------- | ----------------- |
| `NORMAL` | `A >= R + 4`          | 40                           | 50                |
| `TIGHT`  | `R + 1 <= A <= R + 3` | 25                           | 35                |
| `FINAL`  | `1 <= A <= R`         | 15                           | 25                |
| `LAST`   | `A = 0` или 18-й ход  | по строке                    | по строке         |

`turns_left = min(остаток сообщений дня - 1, floor(остаток токенов месяца / оценка на ход))`, где
оценка на ход — среднее трёх последних ходов × 1.2 (`TOKENS_ESTIMATE_FACTOR`). Остаток сообщений дня даёт
`reserve_message`; расход месяца читается из `usage_counters`. Месячный бюджет — константа
`MONTHLY_TOKEN_BUDGET`, пока лимита нет в `entitlements` (`shortcut` в коде).

Предупреждение об остатке звучит один раз при **входе** в `TIGHT` и `FINAL` (переход режима относительно
`pacing_mode` прошлого хода), спокойно и в характере.

## 5. Слова

- Слово `k` вводится не позже хода `2k`; пятое — к девятому ходу. Естественное расписание — ходы 1, 3, 5, 7, 9
  (`next_word_due`), дедлайн — `wordDeadline(k)`.
- Расписание ставит сервер; на ходу с ошибкой по правилу слово не вводится, кроме `FINAL` и случая, когда
  ход — последний по расписанию (дедлайн сильнее мягкого гейта).
- Одно слово за ход; в `FINAL` допускается до двух слов в одном предложении викторины.
- Статусы: `hidden` → `introduced` (карточка показана и авто-добавление в словарь в тот же момент) →
  `recognized` (верный ответ викторины с этим словом) → `produced` (ученик употребил слово сам).
- Модель никогда не спрашивает «добавить в словарь?» и не перечисляет слова списком.

## 6. Викторины

- В `S3 PRACTICE` викторина обязательна не реже двух ходов из трёх (`turn_index % 3 !== 0`) и всегда
  после значимой ошибки; в `S4 CHECK` — так же.
- Ротация `choice` / `gap-fill` / `word-order`; один тип не идёт три хода подряд.
- Маппинг: неверное время → `choice`, неверная форма → `gap-fill`, порядок слов → `word-order`
  (поле `corrections[].errorType`, по умолчанию `form`).
- После трёх верных ходов подряд — задание на собственное предложение (`sentence`), тип викторины для
  обязательной проверки берётся из ротации.
- Повторная ошибка: карточка короче (тот же `choice` с двумя вариантами), третья ошибка: верное предложение
  одной строкой, паттерн помечается слабым и урок возвращается в `S4 CHECK`.

## 7. Fallback сервера

- `next_word_due`, а модель не отдала карточку слова — сервер собирает её из состояния урока
  (`fallbackWordCard`): слово, значение и пример урока.
- Викторина обязательна, а модель её не отдала — сервер собирает её сам (`fallbackQuiz`) из примера слова:
  пропуск, выбор (верный вариант не первый) или сборка предложения.
- Разбор правки остаётся минимальным: сервер ничего не выдумывает, ход не теряется.

## 8. Ответ викторины и данные клиента

- Клиент присылает выбранный вариант полем `quizAnswer` вместе со следующим сообщением.
- Сервер сверяет его с верным ответом сохранённой карточки (`history.lastQuiz`), а не с тем, что пришло от
  клиента: клиент не решает, верно ли он ответил, и не двигает метрики правила и статусы слов.
- Квота, уровень, персонаж и план урока клиенту не доверяются: они выводятся на сервере.

## 9. Промпт

Основа — английский, объяснения на `explanationLocale` не длиннее одного-двух предложений. A1–A2: предложения
3–8 слов и перевод под примерами; B1: 8–12 слов без перевода; B2+: перевод по просьбе. Каждый ход состоит из
двух частей, вторая (`followUp`) заканчивается явной командой в 2–6 слов; один вопрос на сообщение.
Per-turn блок `LESSON_STATE` несёт этап, темп, остаток ходов, сцену, рамку предложения, слово к вводу,
требование викторины, слабые паттерны и лимиты длины частей. Эмодзи запрещены.

## 10. Характер

Реестр `TUTOR_STYLE_CARDS` (`server/tutorCatalog.ts`) задаёт упаковку хода для десяти репетиторов: Мия —
тёплая и без слова wrong; Оскар — методичный; Луна — спокойная («мы», no rush); Макс — сухой, ирония по
ситуации, не по ученику; Алекс — лёгкий, отступление одной строкой; Зои — остроумная, абсурдные примеры;
Нова — строгая, причина со словом because, без лести; Кай — дотошный («prove it»), смягчается после верного;
Лира — прямая и заботливая, сразу говорит, как исправить; Орион — рассудительный, одна ирония на ход.
Характер меняет упаковку, не структуру. При расстройстве ученика острые черты на ход молчат; эмодзи
запрещены, восклицаний не больше одного, опенер и похвала не повторяются два хода подряд.

## 11. Сиды

Каталог — 20 сцен (аэропорт, колл-центр, кафе в час пик, стадион, переезд, космическая станция, музей,
кулинарное шоу, слежка, зоопарк-вебка, фестиваль, видеозвонок со сбоем, съёмочная площадка, почта в
праздники, горная хижина, редакция, склад, школа танцев, пляжный патруль, ночная смена). Сцены последних пяти
уроков пользователя исключаются. Твист появляется после шестого хода. Утро, выходные и семья упоминаются,
только если сцена их разрешает (`allows`). Тип активности не идёт три хода подряд; рамка предложения — из
круга длиннее трёх, поэтому внутри трёх ходов подряд не повторяется.

## 12. WRAP

Итоговый ход (`S6`): сервер отдаёт блок слов урока со статусами (`words` в событии `done`), модель пишет одну
строку-подводку и одну строку о следующем шаге, вопросов нет.

## 13. Отклонения от исходной формулировки задачи

- В документ состояния добавлены два поля, которых нет в перечислении: `weak_patterns` (шестой раздел
  спецификации требует пометку слабого паттерна) и `checks_done` (требование «после двух проверок» в `S5`).
- Проверка ответа викторины идёт по карточке, сохранённой в `messages.payload`, а не по отдельному полю
  состояния: так верный ответ хранится ровно там, где его видит ученик.
- Рендер блока слов и передача `quizAnswer` из карточки викторины в поле ввода — вне списка файлов задачи
  (в клиенте менялись только `src/api/chat.ts` и `src/hooks/useChat.ts`): клиентская часть ограничена
  транспортом, поэтому UI-проводка остаётся следующим шагом.
- Экран карточки цели (`LessonGoalCard`) показывает шаг плана C-10, а не этап движка: контракт DTO не менялся.
