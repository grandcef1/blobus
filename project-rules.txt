# BLOBUS PROJECT - COMPREHENSIVE DEVELOPMENT RULES
# Senior Architect Guidelines for AI Code Generation

## 🎯 CORE PHILOSOPHY (MOST IMPORTANT)
You are designing a PREMIUM, UNIQUE SaaS product. The design MUST NEVER look:
- Template-based or generic
- AI-generated (avoid common AI patterns: excessive gradients, random animations, boilerplate layouts)
- Over-engineered or cluttered

The design MUST always look:
- Minimalist, elegant, and intentional
- Premium and polished (every pixel matters)
- Unique with custom design decisions
- Professional and trustworthy

## 🔒 SECURITY & DATA HANDLING (NON-NEGOTIABLE)
1. **API Keys & Secrets**: 
   - NEVER expose API keys (OpenAI, Supabase) on frontend
   - Store exclusively in backend `.env` files
   - All sensitive operations through Node.js/Express backend

2. **Authentication Errors**:
   - Use toast notifications for auth failures
   - Auto-redirect to login after 3 seconds with message

3. **Input Validation**:
   - Always validate on BOTH frontend (UX) and backend (security)
   - Use Zod schemas for type-safe validation
   - Sanitize all user inputs

4. **Error Logging**:
   - Console.log ONLY in development mode
   - In production: send errors to backend logging endpoint
   - Never expose stack traces to users

##  UI/UX DESIGN PRINCIPLES

### Visual Design:
- **Color Palette**: Monochrome base (#f0f0f5 on black) with strategic accent colors
- **Typography**: Clear hierarchy, generous whitespace, readable line-heights
- **Spacing**: Use Tailwind's spacing scale consistently (no arbitrary values unless necessary)
- **Borders**: Subtle (`border-white/5`), increase on hover (`border-white/15`)
- **Effects**: 
  - `backdrop-blur-xl` for glassmorphism
  - Subtle radial gradients for depth (not flashy)
  - Micro-interactions only (avoid excessive animations)

### Loading States:
- **Skeletons**: For page loads and large data sets (match final layout structure)
- **Spinners/Progress**: For specific actions (file upload, form submission)
- **Timing**: 
  - Show skeleton immediately
  - If loading < 300ms, skip animation (avoid flicker)
  - Use smooth transitions (300-500ms)

### Error Handling:
- **ALL errors via toast notifications** (use shadcn Toast component)
- Inline validation messages for forms (below input fields)
- Never use browser alerts or confirm dialogs

### User Feedback:
- Success toasts: Green accent, auto-dismiss after 3s
- Error toasts: Red accent, auto-dismiss after 5s with retry option
- Info toasts: Blue accent, auto-dismiss after 4s

### Component Patterns:
- **File naming**: `ComponentName.tsx` (PascalCase)
- **Single responsibility**: One component per file
- **Size limit**: Max 150 lines per component (extract if larger)
- **Props interface**: Always define explicit `interface ComponentProps`
- **Default exports**: Use named exports for components

### Type Safety:
- **NO `any`** - strictly forbidden
- Define all types explicitly
- Use TypeScript's strict mode features
- Generic types for reusable components

### Comments & Documentation:
- **Detailed comments** with `// ARCHITECT:` prefix for important decisions
- Explain WHY, not just WHAT
- Document complex logic and edge cases
- Include performance considerations in comments

## ⚡ PERFORMANCE & OPTIMIZATION

### React Optimization:
- Use `React.memo()` for components re-rendering frequently with same props
- `useMemo` for expensive calculations (>1ms)
- `useCallback` for functions passed as props to memoized components
- Lazy load routes with `React.lazy()` + `Suspense`
- Code splitting for large components

### Image & Asset Optimization:
- Use WebP format with fallbacks
- Lazy load images below fold
- Specify width/height to prevent layout shift

### Bundle Size:
- Tree-shake imports (import specific, not entire libraries)
- Dynamic imports for heavy libraries
- Monitor bundle size (alert if >500kb initial load)

##  ANIMATION GUIDELINES (Framer Motion)

### Performance:
- Use `whileInView` with `viewport={{ once: true, amount: 0.3 }}`
- Prefer CSS transforms over position changes
- Use `layout` prop for layout animations (automatic FLIP)

### Transform Conflicts:
- NEVER apply multiple transforms to same element
- Use nested divs: outer for position, inner for scale/rotate
- Example:
  ```tsx
  <motion.div animate={{ y: 20 }}>        {/* Layout transform */}
    <motion.div animate={{ scale: 1.1 }}> {/* Visual transform */}
      Content
    </motion.div>
  </motion.div>
Animation Philosophy:
Subtle and purposeful (avoid "animation for animation's sake")
Duration: 200-500ms (faster for micro, slower for page transitions)
Easing: easeOut for entrances, easeInOut for continuous
Stagger children with staggerChildren: 0.1
